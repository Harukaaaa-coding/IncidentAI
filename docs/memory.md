# Memory and bounded context

`internal/memory` uses only Go's standard library. Working state is stored as JSON under `<data-dir>/incidents/<incident-id>.json`; temporary files are synced and renamed in the same directory. IDs cannot escape the data directory. The package serializes readers and writers across Store instances in one process. Run one application process per data directory; there is no cross-process filesystem lock.

Episodic experience is an append-only journal at `<data-dir>/memories/audit.jsonl`. Each event contains a complete memory snapshot, event time, action and previous review status. Candidate creation always forces `candidate`, ignoring any caller-supplied review state. `Review` accepts `confirmed`, `probable`, `rejected` or `outdated` and records the supplied human identity and time. Confirmation requires evidence references and a resolution. HTTP authentication/authorization belongs to the caller; this package cannot prove a supplied reviewer name is a human. The journal is authoritative, so state cannot change without a corresponding audit entry. A corrupt or interrupted journal fails closed instead of silently dropping review events. Back up the data directory; this is local storage, not a distributed database.

`Search(Query)` returns only confirmed episodic records. Candidates, probable, rejected and outdated lessons remain visible to review APIs but never enter search results. Semantic documents in `knowledge/v2/*.json` carry service, incident type, severity, date, root cause, resolution, environment and status metadata. They are explicitly synthetic reference runbooks, not claimed real historical incidents. A source marked confirmed means maintained reference material; it does not validate a current incident hypothesis.

Retrieval uses BM25 keyword scoring plus cosine similarity of deterministic 256-dimensional hashed concept features. A small checked-in synonym dictionary maps terms such as DB/Postgres/database and deploy/release/deployment. This is local lexical/concept retrieval, **not neural embeddings or a remote vector service**. Hash collisions alone cannot produce a result: actual token/concept overlap is required. Environment is a hard metadata filter (with `all`/unspecified documents shared); service and incident type are ranking boosts so dependency precedents remain discoverable. A bounded recency boost favors newer references. Scores are ranking scores, not confidence probabilities. Both source flags false defaults to both sources; an ablation disabling all knowledge should skip the search call.

`BuildContext(records, budget)` ranks metrics, deployments, diffs and error signals, aggregates repeated logs, compresses verbose records and emits source-labelled blocks. The budget is a hard **Unicode character/rune count for Context.Text**, including reference headers. It is not a token limit; `estimated_tokens` uses an explicitly approximate Latin/non-ASCII heuristic. Raw data remains with the caller for subsequent targeted inspection. The returned source list covers selected evidence, and log groups retain exact counts plus up to three representative raw record references. Log input can be plain lines, JSON lines, JSON arrays, or objects with a `logs`/`entries` array. Summary counts describe supplied entries only. Context metadata is an API inspection aid and is not included in the text budget.

All model inputs should use `Context.Text` rather than serializing the entire Context or raw tool output. History is a precedent; current metrics, logs and code must verify any hypothesis before recovery planning.

Run `go test ./internal/memory` for persistence/restart, concurrent access, review isolation, ranking, provenance and 20,000-log compression coverage.
