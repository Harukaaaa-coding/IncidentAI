# Incident Control Center

V2 前端位于 `internal/platform/web`，由 Go 服务嵌入。使用原生 HTML、CSS、JavaScript，无 CDN、安装步骤或前端构建依赖。桌面为三栏，窄屏将事故列表和证据区域重新排列。

## 使用流程

1. 点击左栏 `＋` 或首页场景卡，选择故障类型和单 / 多 Agent 编排。
2. 创建事故后点击「开始调查」。调查执行期间每秒读取当前事故快照，显示实际计划、工具证据和状态。
3. 在「根因假设」点击证据编号，右栏展开对应来源和原始工具结果。支持度标明为未校准评估值。
4. 审阅恢复建议后点击「批准并执行恢复」。请求携带动作 ID 和当前事故 revision，后端仍负责最终策略检查。
5. 只有服务返回 `resolved` 才显示恢复通过。复盘包含摘要、影响、时间线、根因、证据、处置、预防措施。
6. 在复盘中审阅候选经验并标记 confirmed / probable / rejected / outdated。经验库可按质量状态过滤。

「评测」运行基准并显示真实返回的指标、消融和案例明细；「平台能力」显示引擎、模型、已注册工具、Skills 和风险策略。离线规则基线与 LLM 模式明确分开，Agent 数量不代表调用了语言模型。

## 接口与交互

所有请求使用同源 `/api/v2/*`。新建、调查、审批、经验审阅和评测使用 JSON POST。空数组和缺失字段显示空状态；接口错误显示可关闭提示，不伪造调查结果。审批按钮只在事故待批准、动作 proposed 且策略 approval 时可用，执行中防止重复提交。恢复失败或证据不足时可重新调查。

后端数据通过 DOM `textContent` 展示，不作为 HTML 或脚本执行。提供键盘焦点、跳转主内容链接、图表文本说明、原生对话框和状态提示。模型凭证不会从前端读取或传输。

本地语法检查：`node --check internal/platform/web/app.js`。已用内存 DOM smoke 验证非可信文本、缺失字段、审批门禁、证据展开、四页导航、复盘、重新调查和创建空态。浏览器验收应覆盖创建 → 调查 → 证据展开 → 人工批准 → 验证 → 复盘 → 经验审阅，以及窄屏和错误状态。

评测报告按「指标行 × 实验配置列」对比完整基线、无 RAG、无 Memory、无上下文处理、单 Agent。比例显示为百分数；费用等 `null` 值显示为不可用符号 `—`，不会换算为零。每组案例结果可展开独立检查。
